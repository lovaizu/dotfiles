# README

- Before you add a README change to a task, ask the user whether a reader would make a mistake without the change. The change must be about something that the changed files don't show. If the answer is no, don't change the README. A manual step belongs in the README only when `./setup.sh` can't say it itself, as with installing the font on Windows. In GitHub Issue #27, the work planned a README note without asking the user, and then reverted all of it. `./setup.sh` already said what the user had to do by hand. The reason for the choice of keyboard key wasn't something that a reader would want to undo.
- Keep config values such as font names, colors, theme names and key byte sequences out of the README, and write the reason for the value instead. When two places keep the same value, the copy in the README goes out of date first.
