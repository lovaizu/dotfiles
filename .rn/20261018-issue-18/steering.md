# Goal

ユーザーに判断を求めるとき、開いている判断は常に1つだけにする(Issue #18)。
まとめて聞かれると1件ずつ議論できず、1件目への答えを2件目に生かすこともできない。外から似て見える2件が
逆の答えになることもあり、1つの A/B/C ではそれを言いにくい。会話の中では何度か直してきたが、
リポジトリのどこにも書かれていない。

どのプラグインやリポジトリにも依らない Claude とユーザーの話し方なので、基本方針として
`claude/CLAUDE.md` の既存の「判断が要るとき」の項目を広げる形で書く。

# Acceptance criteria

## Attractive quality

- A1: 判断を求められるとき、毎回1件だけについて答えればよく、押し返したり、その答えを次の件に生かしたりできる

## Must-be quality

- M1: 1つの問いの中で2件を扱わない(2つの質問も、2件を1つにまとめた選択肢も出さない)
- M2: 答えを待っている間に2つ目を送らず、開いている問いを書き換えて後から見つかった件を含めない
- M3: 待っている間も、その判断に依らない作業は止めずに進める。後回しにした件があることが見えないときは
  1行で伝え、その1行は問いにしない
- M4: 既存の項目(結論と根拠、推奨1つの選択肢、詳細は聞かれたら)の意味は変わらない

# Assumptions

- Fact, Issue #18 で確認: 置き場所は `claude/CLAUDE.md` の既存の判断の項目の延長。新しい項目を下に足さない
- Fact, `setup.sh:51` で確認: `claude/CLAUDE.md` は `~/.claude/CLAUDE.md` へ配置され、全プロジェクトで読まれる
- Assumption: `claude -p` で、判断が2件出る場面を与えると、変更前はまとめて聞き、変更後は1件ずつ聞く違いが見える
