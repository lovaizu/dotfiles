## 未検証のまま残るもの

- **WSL 実機**: 3者が `uname`/`cmd.exe`/`wslpath` のスタブでシェル論理を通したが、実物の `cmd.exe`・DrvFs 上の rename の原子性とモード・Windows Terminal の再読込は未確認。次回 Windows 同期時
- **iTerm2 と Windows Terminal 自身の挙動**: 壊れたファイルに対して走らせる手段がここに無く、Python の `json` を代役にした(コメントにその旨を明記)。herdr だけは実物で確認できたので実物の証拠に差し替え済み
- **herdr がテーマ保存のたびに config.toml を書き戻す**: 既存の記述(setup.sh の herdr ブロック)と `onboarding` / `[theme]` がファイルに在る事実と整合するが、書き戻しの瞬間は今回捕捉していない
- **herdr が既定プロファイルでない場合の iTerm2 警告分岐**: `defaults` が `$HOME` を無視して実ユーザ設定を読むため偽 HOME で隔離できず、実機の既定 GUID が `setup.sh` のリテラルと一致していて分岐しない。GUID が `iterm2/herdr.json` の `Guid` と一致することは確認済み
- **Homebrew 未導入機のフォント導入経路**: この機械は導入済みで `already installed. Skipping.` しか通らない
