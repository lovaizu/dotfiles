### Method applied

- **Syntax**: `bash -n setup.sh` → exit 0. `shellcheck` is not installed on this machine (`command -v shellcheck` empty), so it was skipped.
- **Real run (brew present)**: `./setup.sh` → exit 0. Both target files verified byte-identical to the repo sources via `cmp`. Brew branch taken: `brew list --cask font-hackgen-nerd` succeeded (cask 2.10.0 already installed), so the idempotent guard printed "font-hackgen-nerd already installed. Skipping." and no install was attempted.
- **No-brew branch**: verified by running the whole script in a restricted-PATH subprocess (`env PATH=/usr/bin:/bin ./setup.sh`) that still has coreutils/uname but not `/opt/homebrew/bin` — exit 0, manual-install message printed, script continued past the font step. The duplicate `.bak` files created by this simulation run were removed afterwards.
- **Brew failure semantics (documented decision)**: a genuine `brew install --cask font-hackgen-nerd` failure (e.g. network) propagates via `set -e` and exits non-zero with brew's own error — not silently swallowed. This does not conflict with the criteria, which require success only when Homebrew is *absent* (handled by the `else` message path).
- **WSL equivalence**: `git diff` review shows the `*)` arm is the old WT block character-for-character apart from indentation; no command, path, or message changed. Darwin can never reach it because the `Darwin)` arm matches first.
- **set -e safety on Darwin**: the previously fatal line (`wslpath`/`cmd.exe` at top level) now exists only inside the non-Darwin case arm; the Darwin arm uses only `mkdir -p`, `backup_then_copy`, `command -v` inside `if` conditions, and guarded `brew` calls.
