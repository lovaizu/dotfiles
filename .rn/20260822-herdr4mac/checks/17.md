## 落とした重複と、判断の理由

| 対象 | どうしたか | 理由 |
|---|---|---|
| ダウンロード対象の説明(「ファイル名に `_NF` が付くアーカイブ」「その中の Console 版の ttf」) | 落とした | フォント名を伏せた別表現でしかなく、正体を復元できる(`_NF` + `Console` は配布物の版そのもの)。しかも `face` の値が同じ情報を**版まで含んだ1つの名前**として既に持っているので、README 側は二重に持っていた。落としても、読者は名前どおりのファイルを選べばよい |
| brew の cask 名 `font-hackgen-nerd`(Mac 節) | 落とした | setup.sh を読んで確かめた: cask を install するのは `./setup.sh` 自身(`brew list --cask` / `brew install --cask` の分岐)で、読者がコマンドを打つ場面が無い。唯一打つ可能性がある「失敗後の再実行」も、setup.sh の `warn` がコマンドを丸ごと表示する(その `Fix:` 行)。**README に無くても手順は成立する**。#8 は「実行するコマンドそのもの=手順」として残したが、実行するのは読者ではなく setup.sh なので、この判断は成り立たない |
| WT のプロファイル名の列挙(`PowerShell / Ubuntu / ClaudeCode / my など`) | 落とした | ユーザーのプロファイル在庫のスナップショットで、1つ増やせば古くなる。その文の主張は「`profiles.defaults` に置けば全プロファイルが継承する」で、名前は1つも要らない。代わりに「プロファイルを増やしても設定を足す必要が無いのが狙い」という**意図**を書いた — 在庫が変わっても真であり続ける |

## 残した重複と、割に合う理由

| 対象 | 直す必要が生じる変更 | 割に合う理由 |
|---|---|---|
| 配布元へのリンク `https://github.com/yuru7/HackGen/releases`(WSL 節・Mac 節から参照) | **配布元が変わったとき、およびフォントを別のものに変えたとき**(URL にフォント名が含まれるため、フォント変更は README の1行を直すことを必ず伴う) | 落とす対象は「変更したときに同期を取る必要が生じる**値**」で、リンクは値ではなく**ポインタ** — README が担う「手でやるしかない箇所」の中身そのもの。これを落とすと完了基準3が成立しない: setup.sh の2つの warn(brew install 失敗 / Homebrew 不在)は `install the font by hand (see README)` と読者を README に送るので、README が入手先を持たなければ**参照が輪になって読者はどこにも着かない**(名前を持って Web 検索させるのは「README と設定ファイルだけで辿れる」ではない)。性質は iTerm2 のメニュー名と同じで、**受け入れた費用**として扱う。費用は明示しておく — フォントを別のものに変えれば、設定ファイル2つに加えて README のこの URL も直すことになる。緩和として、README が持つのは**リンク1本だけ**にした(リンクテキストにフォント名を書かず、アーカイブの命名規則も戻さない)ので、直す箇所は1行・1回で済む |
| 配置先パス(`%LOCALAPPDATA%\Packages\...\settings.json`、`~/Library/.../DynamicProfiles/herdr.json`、`${XDG_CONFIG_HOME:-...}/herdr/config.toml`) | 配置先そのものを変えたとき(= setup.sh の構造変更) | 「何がどこへ配られるか」は README の担当そのもの(**何ができるか**)で、これを落とすと読者は setup.sh を読むしかなくなる。動くのは配置方式を変えたときだけで、それは滅多に起きず、起きたときは README を読み直すべき変更でもある |
| 退避先 `${XDG_STATE_HOME:-$HOME/.local/state}/dotfiles-backups` | 退避先を変えたとき | 同上に加えて、**退避先はどのプログラムも読まない**(design.md §4.6)ので、書いてある場所が README だけになりやすい。「増え続けるので自分で消せ」という運用の指示は、パスが無いと実行できない |
| 設定項目名(`profiles.defaults.colorScheme` / `profiles.defaults.font` の `face`/`size` / `[theme]` / `[keys]` / `Normal Font` / `actions`・`keybindings` / `Keyboard Map`) | 設定ファイルのスキーマが変わったとき(外部アプリの都合、または herdr の都合) | **値を落とした README から設定ファイルへ辿るための唯一の手掛かり**で、これを落とすと完了基準3が成立しなくなる(今回のフォントの記述はまさにこれに依存している)。動くのはスキーマ変更のときだけで、それは値の変更とは頻度が2桁違う |
| キー対応表(`Ctrl+Alt+[` / `⌃⌘[` など) | 割り当てるキーを変えたとき | これは**故障ではなく正しい挙動**。「両 OS で指運びが揃う」がこのリポジトリの目的そのもので、キーが変われば揃え方の宣言も変わる。README は対応表の**正**(design.md §4.1: 両翻訳ファイルは README の対応表に従う)であって、写しではない。落とすと「両 OS で何が揃っているか」を述べる場所が消える |
| `Other Actions... > Set as Default`(iTerm2 のメニュー名) | **iTerm2 が UI を変えたとき**(外部アプリの都合で、こちらの変更と無関係に古くなる) | 配置先パス以下の4つは「こちらが何かを変えたときだけ動く」が、これは**外部の都合で勝手に古くなる** — 表の先頭の配布元リンクと同じ性質。それでも残すのは、この操作が自動化不可能な必須手作業(#17 の完了基準3が守る「手順」)で、メニュー名なしでは実行できないため。緩和はしてある — setup.sh もこの文字列を持つが、`iterm_default_menu` という**変数1つ**に集約されていて(setup.sh の `iterm_default_menu` を、既定プロファイルについての2つの warn が参照する)、iTerm2 が名前を変えたときに直すのは README とその変数の2か所で済む。0 にはできないので、これは受け入れた費用 |
