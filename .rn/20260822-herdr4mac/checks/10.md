## 積み残していた指摘と対応

| 指摘 | 対応要否 | 対応内容 |
|---|---|---|
| **一時ファイルの先頭ドットの理由がコメントで逆に書かれている** — 「iTerm2 は DynamicProfiles の全ファイルを読む」は偽 | 要 | 自分でも実測(`strings /Applications/iTerm.app/Contents/MacOS/iTerm2` に `Skipping it because of leading dot` / `Skipping it because of trailing tilde (GNU-style backup file)` が `reallyReloadDynamicProfiles` の近傍にある)。`BACKUP_DIR` と `tmp_prefix_for` の2箇所を書き直し、「ドットで始まるから読み飛ばされる = 一時ファイルが安全」「`.bak` はどちらの規則にも当たらないから隣に置けない」という向きに揃えた |
| **`backup_file` の一時ファイルが trap にも sweep にも入っていない** | 要 | 一時ファイル名を `deploy` 側で決めて `backup_file` に渡す形にし、trap(`remove_pending_tmp`)が配置用と退避用の両方を消すようにした。合わせて `deploy` が `BACKUP_DIR` 側のパターンも毎回掃く。実測: 退避コピーの途中でプロセスグループへ SIGINT — 修正前は 40 バイトの `.config.toml.dotfiles-tmp.<pid>` が残り、収束後の3回の run を生き延びた。修正後は中断直後に BACKUP_DIR が空、SIGKILL で残した場合も次の1回で消える |
| 「the next run sweeps it」が偽 | 要 | 上の変更で実際に真になった(`deploy` が毎回掃くので、収束済みの run でも掃く)。コメントも「trap が消す/殺された run のぶんは deploy の sweep が拾う」と書き直した |
| `$$` の理由が自己矛盾 | 要 | `tmp_for` 側に一本化。「pid があるから2つの run が同じ一時ファイルへ書いて混ざったものを rename することはない。同時実行はそもそも支援しないが、負けた run は自分の rename で失敗する」— sweep 側のコメントと矛盾しない書き方にした |
| 一時ファイル名の形式が2箇所に手書き | 要 | `tmp_prefix_for` を新設し、`tmp_for`(pid を付ける)と `sweep_tmp_files`(`*` を付ける)の両方がそれを使う。形式を組み立てるのは1箇所だけ |

| `windows-terminal/settings.json` が index で 100755 | 要 | `git update-index --chmod=-x` と `chmod 644`。実測: WSL スタブ経路で配置すると `-rw-r--r--` で落ちる |
| `${#FAILURES[@]}` ガードに理由が書かれていない | 要(コメント追加) | 自分で実測してから記載(`/bin/bash -c 'set -u; arr=(); echo "${arr[@]}"'` は `arr[@]: unbound variable` で exit 127)。「体裁ではない」と明記した |
| 失敗時の `Fix:` 文が権限の話しかしない | 要 | リポジトリ側の原本欠落を先に分岐させた。「`No such file or directory` が `$DOTFILES_DIR` 配下を指しているならクローンが不完全」「それ以外はこのマシン側」。実測: 原本を消したコピーで踏ませて文面を確認 |
| **配置に失敗した run が空のディレクトリを残す** | 要 | **消さず、メッセージを直す**方を採った。`mkdir -p` は「この run が作ったか」を返さないので、消すなら元からあったディレクトリを消す覚悟が要る。空ディレクトリは無害で、次に成功する run が埋める。失敗メッセージから「leaves nothing to undo」の断定を外し、「空のディレクトリが残ることがある」と述べる。design.md §4.6 に境界として追記 |
