## 前ラウンドの指摘と対応

いずれも隔離ホーム(`env -i HOME=…`)で `/bin/bash` 3.2.57 により再現・確認した。

| 指摘 | 対応要否 | 対応内容 |
|---|---|---|
| **退避先をグローバル変数で持っており、あとの配置の失敗が、前の配置がユーザーに約束した退避を消す**(データ消失) | 要(ブロッカー) | `backup_file` の stdout から `deploy` のローカル変数で受ける形に変更。3ケースで約束された `.bak` が run 後も残ることを確認 |
| **読み取り専用の配置先に対し、tty があると `mv` が確認プロンプトを出して既定 "n" で何もせず exit 0 を返す** — スクリプトは `Installed` と表示し、一時ファイルも残る(偽の成功) | 要 | `mv -f` にした。pty 越しの実測でプロンプトなし・実際に上書き・一時ファイル0 |
| SIGKILL で残った一時ファイルを誰も消さない | 要 | `deploy` が配置の前に配置先ディレクトリの同じパターンを掃く。配置先が既に原本と一致している run でも掃く |
| Ctrl-C で死んだ退避が「完全な退避」を名乗る名前(`.bak`)で残る | 要 | 退避も一時名で書いてから rename する方式に変更。SIGINT で `.bak` は0本 |
| シンボリックリンクに関するコメントが実挙動と違う | 要 | 実測に合わせて修正(内容一致→リンクのまま、不一致→実体に置換、リンク先は無傷) |
| 失敗サマリが「他はすべて配置した」と言うが、配る先が無くてスキップしたものがある | 要 | `Everything else was deployed or skipped as noted.` に変更。design.md §4.6 の境界に第3カテゴリを新設 |
| herdr 不在時のメッセージが、直後が `Up to date` の run で「これからインストールする」と読める | 要 | `herdr not found. Its config is managed here all the same:` に変更 |
