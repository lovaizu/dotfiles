## `hooks.SessionStart.[].hooks is replaced whole` の警告について

実機の初回マージで出た。要素単位マージは `matcher` で突き合わせるところまでで、その要素の**中**の
`hooks` 配列は葉として置き換わる(design.md §4.7)。今回置き換わった中身は
`bash '/Users/kiyo/...' session` → `bash "$HOME/..." session` で、これは意図した変更そのもの。
警告は「dst 固有のものが消えたかもしれない」を機械的に言うもので、消えたものは無い(diff で確認済み)。

### 設計ドキュメントとの整合

- `design.md` §4.7: id で突き合わせる配列の一覧に `hooks.<Event>` の要素の中の `hooks`(`command`)を追加。
  境界の「内側の `hooks` 配列は葉のまま」を削除し、差し戻しの理由(`matcher: "*"` は SessionStart の
  普通の綴りで、`/config` がその配列に書き込むので dotfiles の単独所有ではない)に置き換えた。
  「マージには削除の概念が無い」に、それが1段内側まで届くこと — dotfiles が `command` の綴りを
  変えると新旧2本が同じ matcher の下で走ること — を追記。あわせて JSON では改行コードが保たれない
  ことも境界に明記した(実測: CRLF の dst が LF で返る。警告は出ない)。
- `tests/README.md`: 「コメント・行順・改行コードが残る」が **TOML だけ**であることを明記(JSON は
  文書を組み直すので JSONC のコメントは落ち、改行は常に LF)。id 突き合わせの配列一覧と
  `realdata.sh` の説明(失敗時 exit 1)も更新。
- 実機の `~/.claude/settings.json` は既に `"$HOME/…"` 綴りのフックを1件だけ持つので、この変更で
  次回 `setup.sh` を流してもフックが2本になることはない(上記「削除の概念が無い」の但し書きは、
  今後 `command` の綴りを変えたときに効く)。
- 本ファイル上部の「`hooks.SessionStart.[].hooks is replaced whole` の警告について」は #7 時点の
  記録で、V1 の修正でその挙動自体が無くなった。記録としてはそのまま残す。
