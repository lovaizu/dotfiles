### Method applied

- **JSON validity**: `python3 -m json.tool iterm2/herdr.json` → exit 0, no output ("json.tool OK").
- **Keycode arithmetic** (NSEvent flags: Shift=0x20000, Ctrl=0x40000, Cmd=0x100000; key = unmodified char code):
  - `⌃⌘[`: char `[` = 0x5b; Ctrl|Cmd = 0x40000+0x100000 = **0x140000** → `"0x5b-0x140000"`
  - `⌃⌘]`: char `]` = 0x5d; same mods → `"0x5d-0x140000"`
  - `⌃⌘U`: char `u` = 0x75 (lowercase, unmodified) → `"0x75-0x140000"`
  - `⇧Enter`: Return = 0xd; Shift = **0x20000** → `"0xd-0x20000"`
  - 2-part key form (no trailing keyboard-type segment) used for broad compatibility.
- **Byte encoding choice**: Action 12 (SEND_TEXT) with the literal control character embedded via the JSON escape backslash-u0014 (`\u0014`, ^T = 0x14) followed by the literal ASCII char; Shift+Enter uses JSON `\n` (literal LF 0x0a). SEND_TEXT passes literal characters through as-is, so payloads are byte-exact and were verified by decoding `Text.encode()` → hex: `145b`, `145d`, `1475`, `0a` — all match the README table. Chose Action 12 over Action 10 (ESCAPE_SEQUENCE, which prepends ESC — wrong for ^T-prefixed bytes) and Action 11 (HEX_CODE, also viable but the literal-text form is directly diffable in JSON).
- **Color conversion**: hex→float table verified programmatically; sample rows: `#282828`→0.1568627450980392 (40/255), `#CC241D`→(0.8, 0.1411764705882353, 0.11372549019607843), `#EBDBB2`→(0.9215686274509803, 0.8588235294117647, 0.6980392156862745), `#FFFFFF`→(1.0, 1.0, 1.0). All 20 dicts carry `"Color Space": "sRGB"` and `"Alpha Component": 1`. Mapping WT→iTerm2: black..white→Ansi 0–7, brightBlack..brightWhite→Ansi 8–15, foreground→Foreground, background→Background, cursorColor→Cursor, selectionBackground→Selection. Full comparison exact-equality passed for every entry.
- **Minimality**: profile contains only Name, Guid, Normal Font, Keyboard Map, and the 20 color dicts — no extra keys duplicating iTerm2 defaults.
