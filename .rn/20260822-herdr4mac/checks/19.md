## 落とした内容と、落とせる理由

| 落とした | 再現に効かない理由 |
|---|---|
| キー対応表(操作 / Win キー / Mac キー) | 再現は `setup.sh` がやる。日々どのキーが何かは `herdr/config.toml` の `[keys]` と各端末の設定が持つ。統一が崩れたことに気づける必要は「指運びを揃えている」の1行が (b) として担う |
| 管理対象と配置先の表 | `deploy` の呼び出しそのもの。しかも `setup.sh` は配置のたびに配置先を絶対パスで表示する |
| 退避の仕様(BACKUP_DIR・剪定しない・原本と同一なら取らない) | 退避を取った run は退避先パスを実行時に表示する。取らなかった run は `Up to date` を表示する |
| symlink の扱い(1段落) | `deploy` の warn がほぼ同文を実行時に喋る。README 側は写しだった |
| 失敗したときの挙動(警告→続行→列挙→非0 / スキップは0) | 失敗した run が末尾で列挙して exit 1 する。スキップは `Skipping.` と言う |
| XDG_CONFIG_HOME に従う理由 | 相対値を捨てた run は理由込みの WARNING を出す |
| `profiles.defaults` に置けば全プロファイルが継承する話 | Windows Terminal の仕様であって、この repo の再現に要る情報ではない |
| シェルは統一しない旨 / herdr の起動は手動 | 何もしないことの宣言。再現の手順が1つも増えない |
| README 自身の規則の宣言(「値は設定ファイル側にしか置かない」) | 規則をメタに書くのではなく、規則どおりの README がそこにあればよい |
